# Changelog

## Unreleased

**Backend:** update your server: re-run `apps/dzep-macos-app/tool/setup-backend.sh`, or the Mac's setup wizard on the same project (new migration `20261017090000_reviewer_access.sql`; `ask`, `pair`, `push` and `device` changed; `supabase config push` turns email sign-up off). The publisher redeploys the relay (`tool/deploy-relay.sh`).

- **Project folders**: the Mac's **Settings → Terminals → Project folders** says where your projects are (**Add folder…** opens a folder picker). The phone's **+** lists the git repositories in those folders instead of in `~/Dev`, `~/Developer`, `~/Projects`, `~/code` and `~/src`, so until you add one it lists only folders with a window open, and **New project…** makes a new folder in one of them and opens a session in it (with an older Mac the phone offers no **New project…**).
- **Reviewer access**: revoking a reviewer code that was the last one working signs the demo account out on every phone at once, and a code running out does the same within 10 minutes; Ask turns the demo account away from then on. A reviewer who taps **Delete account** empties the demo account instead of deleting it, so the codes you gave Apple or Google keep working for the next review.
- **Sign-up only through GitHub**: email and password sign-up is off, and the server refuses email, phone and anonymous sign-ups even on a project set up some other way. Pairing phones works as before. If you delete your account but keep the server, unset the AI key or delete the project: the next GitHub sign-in would own it ([docs/SELF_HOSTING.md](docs/SELF_HOSTING.md#removing-it)).
- Pairing: wrong codes are counted per caller only by the address Supabase's edge vouches for (`cf-connecting-ip`), so a client can't dodge the throttle by sending a made-up `x-forwarded-for`.
- Push relay: limits per caller address and per device token, with 429 and `Retry-After` past them (`relay/limits.ts`); [SECURITY.md](SECURITY.md#model) now says what an open relay allows. `push` moves Live Activities only on an explicit state, never on a notification's title, and `device` answers "action must be done" for anything else.
- For contributors: `tool/setup-backend.sh` needs `jq` (part of macOS 15 and later) instead of `plutil`, so it runs on Linux too; it and `deploy-relay.sh` pass secrets in a mode-600 env file, never on the command line. New checks, run in CI too: `supabase test db` (pgTAP), `deno test --allow-env supabase/functions/_tests/` and `deno check` of the omp extensions ([CONTRIBUTING.md](CONTRIBUTING.md#pull-requests)). CI pins the Supabase CLI and its actions, and reads the repo only.
- For contributors: a shorter README, led by one picture of the Mac popup next to the phone, with the setup wizard's steps; the other screenshots and the Terminal diagram moved to [docs/USING.md](docs/USING.md) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#terminals-mac). The screenshot generators also render the setup wizard and that picture ([docs/BUILDING.md](docs/BUILDING.md#screenshots)).
- The iPhone app is iPhone only (no iPad build), and its photo access prompt now says the images go to a question or a coding session.
- For contributors: an Android release build stops without `android/app/google-services.json` instead of shipping without push (`-P allowNoPush=true` builds one anyway), and `tool/release.sh` signs the DMG with the team's own Developer ID certificate, checks that HEAD is on `origin/main`, and lets `gh` create the tag with the release.
- Mac: the coding agents' extensions check that the local API is really Džep (a proof it answers on `/v1/ping` with a fresh nonce) before sending its token or any command; update them from **Settings → Coding agent**. `POST /v1/notify` is gone, and Džep now removes `~/.config/dzep/cli.json` when it quits.
- Mac: Terminal from the phone sees only kitty sockets owned by your own macOS account, so another account's kitty can't show windows here or receive typing.
- A setup link opened from outside the app (a web page, a message, the camera) for a server other than the device's own now asks **Connect to <host>?** before connecting or signing in, on the phone and on the Mac.
- **Delete account** stops before deleting anything if the images on your server can't be removed ("Account not deleted"), and signing out clears the session on the device even when offline, so a relaunch doesn't sign you back in.
- Phones: signing out ends every Live Activity or ongoing session notification at once and tells the server, so it stops updating the old account's sessions.
- Mac: Terminal from the phone restarts its connection whenever the signed-in account changes, including when the server ends the session.
- iPhone: a widget tick or notification **Done** queued while offline can no longer be lost when the app reads the queue at the same moment, and the phone registers for push only once it has made its encryption key.

## 0.3.0

The first release on GitHub Releases; it also carries everything listed under 0.2.0. **Backend:** update your server: re-run `apps/dzep-macos-app/tool/setup-backend.sh`, or the Mac's setup wizard on the same project (new migrations, `ask`, `pair` and `push` changed).

- **Removed: Siri and Action Button shortcuts on iPhone; the widgets stay.** **Backend:** redeploy `device` (`supabase functions deploy device --no-verify-jwt`).
- **Any terminal, not just kitty**: Terminal from the phone now works with iTerm2, WezTerm, Ghostty, Terminal (macOS's) and tmux too. What a window can do depends on its terminal (kitty, WezTerm and tmux everything; iTerm2 without colors; Ghostty without a screen; Terminal without keys), and the phone shows only what works; with tmux installed, sessions the phone starts in Terminal or Ghostty run in tmux with full control. New windows open without taking the focus: in kitty and Ghostty a session from the phone opens as a tab in the window Džep opened last, and an app that still jumps to the front gets the focus back within about a tenth of a second. The Mac's new **Settings → Terminals** shows each terminal as Ready, Limited or Needs setup, sets kitty up in one click (**Set up…**, then restart kitty) and picks where **New sessions open in**. macOS asks once whether Džep may control iTerm2, Terminal and Ghostty; until you answer, the phone says so instead of waiting.
- **Mac popup, browse notes and chats by keyboard**: in Note mode ↓ from the field's last line moves into **RECENT NOTES** (↑/↓ move, ↵ or ⌘O opens the note in the main window, ⌘P in the note window, Esc or ↑ past the top goes back to the field). In Ask mode ↓ from the question's last line lists your recent chats, newest first; ↵ continues the selected one in the popup, ⌘O opens it in the main window, Esc or ↑ past the top goes back to the chat you were on.
- For contributors: a shorter README with screenshots and diagrams; every feature, key and setting is in [docs/USING.md](docs/USING.md). The screenshots are the real screens on made-up data, rendered by `fvm flutter test --tags screenshots --run-skipped` in each app ([docs/BUILDING.md](docs/BUILDING.md#screenshots)).
- **Android app**: everything the iPhone app does. Todos, Ideas, Notes, Ask and Terminal tabs; **Todos** and **New idea** home-screen widgets; reminders with a **Done** action; coding sessions you follow show as an ongoing notification (working, needs you, finished) instead of a Live Activity. Pairs with your server by scanning the Mac's code.
- **Android push**: reminders, omp notifications and session updates reach Android through Firebase Cloud Messaging, encrypted by your server with a key only that phone has, exactly like the iPhone's. The relay only passes ciphertext on. **Backend:** run `apps/dzep-macos-app/tool/setup-backend.sh` (new migration: a `platform` column on `push_devices` and `activity_tokens`; `push` redeployed); the publisher redeploys `relay` with the Firebase service account.
- **Phones only pair**: setting up a server is the Mac's job (its wizard or `setup-backend.sh`); the phone app scans the Mac's code (**Settings → Set up phone…**, formerly "Set up iPhone…") or takes it pasted.
- **Phones sign in only with the Mac's code**: no more GitHub on the iPhone and Android apps. A phone without a session shows **Scan the code from your Mac** and **Paste a code instead** (the same code as text, the whole `dzep://setup?…` link), nothing else; after signing out, a deleted account or a sign-in the server ended, it's back there and says why. The code is a random 28-character code your server keeps only a hash of: it works once, for 10 minutes, and is swapped for a fresh sign-in when the phone uses it. A wrong code reads the same whatever went wrong, and ten wrong ones from one place in ten minutes are turned away for a while. Codes made by an older Mac app no longer work: update the Mac app too. **Backend:** run `apps/dzep-macos-app/tool/setup-backend.sh` or the Mac's setup wizard (new migration: `pairing_codes`, `pairing_failures` and the sign-up hook letting in the demo account below; `pair` redeployed).
- **Reviewer access** (Mac): **Settings → Reviewer access** makes a code for App Store or Google Play review that signs a phone into a separate demo account on your server, so reviewers get in without your Mac. It works as often as needed for 7, 30 or 90 days, shows its QR and link (**Copy**, **Save QR as PNG**), and the active codes are listed with **Revoke**. The demo account sees none of your data, but Ask works for it on your AI key.
- **Connect an AI later**: skipped the AI during setup? Ask now says "No AI connected yet" on the Mac and the phones instead of failing on your first question, and your old chats stay readable. Connect one from the Mac's **Settings → AI** (or **Connect an AI…** in Ask): pick a provider, paste its key and a Supabase access token that is used once and not kept. The same row shows which model Ask uses and switches providers. **Backend:** redeploy `ask` (`apps/dzep-macos-app/tool/setup-backend.sh`).
- **Setup wizard, sturdier**: a new project that takes long to start is waited for again (Continue, or Back and return) instead of a second one being made; the free plan's two-project limit says what to pause. Changes made after **← Back** (GitHub app, AI key, another project) are applied on Retry, Retry remembers "Skip AI for now", and a check that finds GitHub sign-in off sets it again. A wrong GitHub Client ID, secret or callback URL is caught on its step. An existing project is looked at first: one with accounts or tables of the same names is refused with the reason, and settings Džep would replace (Site URL, a sign-up hook, another GitHub app) are named before you go on. A failed connect at the end shows why and can be retried.
- Fixed, Mac **Set up phone…**: when no code could be made it always blamed the connection; it now says why (not signed in, no email on the account, a server too old for pairing).
- **Claude Code, next to omp**: Džep's Claude Code plugin ([integrations/claude](apps/dzep-macos-app/integrations/claude)) brings `/idea`, `/do` and `/note` to Claude Code (no Claude turn, and they work while Claude works), and its sessions to your phone like omp's: the conversation as it's written, prompts with images, Stop, its questions, tool approvals and plan reviews answered from the phone, its slash commands, and pushes and Live Activities when it finishes or needs you ("Claude finished · project"). A prompt sent while Claude works waits for the run to end (Claude Code can't steer a run), so a Claude session's composer has no Steer. Notifications and the phone name each session's agent. Needs Claude Code 2.1.287 or later. **Backend:** redeploy `push` (Live Activities now follow an explicit state; older Macs still work).
- **`/todo` is now `/do`** in omp and Claude Code (`/do call bank !15:00`, `/do list`, `/do done 2`): omp has a `/todo` of its own (its task list), and omp's built-in commands win over an extension's, so Džep's `/todo` never ran there. Update the integration (**Settings → Coding agent → Update**) and restart running sessions.
- **Coding agent setting** (Mac): **Settings → Coding agent** picks what a new session from your phone starts, omp or Claude Code, and the row under it installs or updates Džep's integration for it (omp's extensions in `~/.omp/agent/extensions/`, or the Claude Code plugin from `~/.config/dzep/claude-plugin`), showing whether it's installed and current. Restart running sessions after installing. When Claude Code has mods turned off (it keeps them off until it has fetched its settings while you're logged in), the row says so: run `claude /login`, start `claude` once, then restart your sessions.
- Fixed, Mac: a second Džep (a debug build) took over `~/.config/dzep/cli.json` and left it pointing at nothing when it quit, so omp and Claude Code couldn't reach the Džep you run. Džep now checks the file every few seconds and writes itself back when it names a Džep that's gone, and on quitting removes the file only if it's still its own.
- For contributors: the repo is now a Dart pub workspace. The Mac app and the backend it bundles (`supabase/`, `tool/`, `integrations/omp/`) live in `apps/dzep-macos-app`, the phone app (iOS and Android) in `apps/dzep-mobile`, shared code in `packages/dzep_core`. Run each app's commands in its own directory ([docs/BUILDING.md](docs/BUILDING.md)).
- For contributors: a second Džep for testing can keep away from the one you use: `DZEP_CLI_JSON` and `DZEP_KITTY_DIR` move its terminal API file and the kitty sockets it uses ([docs/BUILDING.md](docs/BUILDING.md#running-a-second-džep-for-testing)).

## 0.2.0

- **Note window** (Mac): a note in a small window of its own, floating over everything (a video, a full-screen app), moved and resized as you like. Open it from a note's header in the main window, which steps aside until you close it and then comes back on that note, or with ⌘P in the popup's Note mode, which takes the note you were writing (or starts a new one) and leaves the app closed when you're done.
- **Smaller main window** (Mac): it now goes down to 480×360; when narrow, the sidebar folds into icons and the list gets narrower before the note does.
- Fixed, Mac popup: opened with the shortcut, its field had no cursor until you pressed a mode key or clicked it; and a draft coming back (Ask, Note, a description) was selected whole, so the next key wiped it.
- Fixed, Mac popup: ⌘O opens the app on the popup's list (Ideas, Todos, Notes, Ask) instead of wherever the app last was.
- Fixed, Mac: ⌘, (Settings), File → Close Window and Džep → Check for Updates… were missing from the menu bar.
- **omp on the Lock Screen**: an omp session you prompt from the iPhone (or follow with the lock-clock button in its top bar) becomes a Live Activity on the Lock Screen and in the Dynamic Island, showing Working with a timer, Needs you (question, approval or plan review), Finished, or Ended, and kept current by push while Džep is closed. A tap opens the session. These pushes carry only that state, never the session's title or text. **Backend:** apply the new `activity_tokens` migration and redeploy `push`; the publisher redeploys `relay`.
- **omp sessions on the iPhone, made for the phone**: the Terminal tab now shows each omp session as a conversation the phone lays out itself, so a narrow kitty window on the Mac no longer means a narrow screen on the iPhone. Answers stream in as Markdown, tool calls are cards with their output, and you can prompt (with images), steer or queue while omp works, stop it, answer its questions and tool approvals, and page back through older messages. Needs the new omp extension [integrations/omp/live.ts](apps/dzep-macos-app/integrations/omp/live.ts) next to `idea.ts`.
- **omp's slash commands from the iPhone**: typing `/` in an omp session's composer suggests omp's commands (its own, plus your extensions', prompts' and skills') with their descriptions, like omp's terminal; a tap (or Tab on a keyboard) fills one in. Commands run in the session's kitty window, so a session without one says so. Update the omp extension ([integrations/omp/live.ts](apps/dzep-macos-app/integrations/omp/live.ts)).
- **Terminal opens at once**: the iPhone keeps the last list, conversations and screens, so they show immediately (marked when the Mac isn't answering) and catch up from where they were.
- **Terminal reconnects by itself**: after the Mac slept, the network dropped or the phone came back from the background, the link could stay dead (the Mac looked connected and answered nothing) until Džep was restarted. Both sides now join again on their own, with a fresh sign-in token.
- omp windows that started before the omp extension was installed say so in the Terminal list: restart omp in them (`omp -c` continues the conversation) to see them as conversations.
- Fixed: text typed while the previous prompt was still being sent was wiped when it arrived.
- kitty screens (shells, omp's own menus) arrive as changes instead of whole every second, keep their place while you read, and a shell's long lines wrap to the phone. The Mac talks to kitty over its socket instead of starting `kitten` for every command.
- **Push notifications on the iPhone**: reminders arrive on time even when Džep hasn't been opened since they were set on the Mac, and a todo ticked off elsewhere no longer goes off. When an omp run ends or omp needs you (a question or an approval waiting) while you're away from the Mac, the iPhone gets a push too; a tap opens that session, also when it launches the app, and none comes while the phone is showing that session. Your server encrypts every notification with a key only your iPhone has; the relay that hands it to Apple sees only ciphertext.
- **Setup wizard**: on first launch the Mac app sets up your server for you (Supabase project, tables, GitHub sign-in, functions, AI key) from a Supabase access token. No repo or CLI needed; `tool/setup-backend.sh` still works.
- **iPhone setup by QR**: Mac **Settings → Set up iPhone…** shows a one-time code (10 minutes); the iPhone app scans it with its own camera and signs in, no GitHub login on the phone.
- **New icon**: a pocket with a note in it ("džep" is Croatian for pocket), in the app icons, the Mac menu bar and the app's screens.
- Fixed: on the Mac, Settings could ignore the gear and Done (the main window didn't redraw on app changes).
- Fixed: the popup could crash at launch when it opened in Ask mode before the chats had loaded.
- Fixed, Mac popup: a key typed right after ⌘1–⌘4 (or reopening the popup) could select the whole draft, so the next key wiped it; characters typed right after the shortcut were lost in Ask; a click on the list, the hint bar or the padding left no field focused, so Esc and typing did nothing until the field was clicked; ⌘W did nothing. The popup's keys now work whatever was clicked, typing goes into the field at its caret, and ⌘W hides it like Esc.
- Fixed, Mac: closing the popup with the shortcut while the main window was in front handed the keyboard to the app used before; it now stays with the main window, as it did after Esc. And whatever you were typing in there (a note, a description, the search) has the cursor again, instead of typing going nowhere until you clicked it.
- **Main window keys**: ⌘N new item, ⌘F or / search, ↑/↓ move through the list, ⌫ deletes the selected item (with Undo), Esc clears the search or leaves a field for the list. They work whatever was clicked last, also after a click beside a field. Settings (⌘,) takes the keyboard even from a focused field, so Esc closes it.
- Fixed, Mac: selecting several lines of a note or description highlighted whole rows out to the widest line, empty lines included; it now covers just the text.
- Mac: key hints use the system font, so ⌘O no longer reads as ⌘0.
- **Notes**: free-text notes next to ideas and todos, first line as the title, saved as you type. In the popup (⌘3), the main window's Notes, the iPhone's Notes tab, Siri ("add a note to Džep") and omp's `/note`.
- **Simpler popup**: it opens straight into the mode you used last; a strip on top (⌘1–⌘4: Idea, Todo, Note, Ask) replaces the 1/2/3/4 chooser, with **Open app** (⌘5) at its far right.
- **Simpler main window**: the sidebar is Todos, Ideas, Notes, Ask and your projects; done todos fold away under the open ones instead of a separate list.
- Quick questions take images: paste with ⌘V or attach with 📎 in the Mac popup and main window, paste or pick from Photos on the iPhone. Up to 4 per question, scaled to 2048 px at most; they show in the chat history on every device.
- Fixed: right after launch the Mac could join the terminal channel before its sign-in was ready, and then never hear the iPhone (its Terminal tab spun forever).

**Backend:** run `tool/setup-backend.sh` (new migrations: `chat_messages.images` with the private `chat` bucket, the `note` kind, and push: `push_devices`, `push_sent`, `push_config` and a `pg_cron` job; `ask` and `device` redeployed; new `pair` and `push` functions; sign-in links valid for 10 minutes, `otp_expiry = 600`). Images need a model that reads them; `deepseek-flash` (V4.1) does.

## 0.1.0

First public release.

- Self-hosted: on first launch, connect your own Supabase project (setup screen or `dzep://setup` link). `tool/setup-backend.sh` sets one up.
- Quick questions work with any OpenAI-compatible API (`AI_BASE_URL`, `AI_MODEL`, `AI_API_KEY`); DeepSeek stays the default.
- Private servers: after the first account, only allow-listed emails can sign up.
- Delete your account, and everything in it, from Settings.
- The Mac app ships as a notarized DMG and updates itself (Sparkle).
- Fixed: a first sync of more than 1,000 items or chat messages missed the older ones.
- Fixed: an image sent from the iPhone stayed in Storage when the Mac didn't answer.
- iOS privacy manifest; omp `/idea` and `/todo` extension in `integrations/omp`.

**Backend:** run `tool/setup-backend.sh` (new migration, `ask` reads `AI_*` secrets instead of `DEEPSEEK_API_KEY`).
